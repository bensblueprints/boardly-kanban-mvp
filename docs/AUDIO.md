# Company, board and project audio briefings

Open **Audio briefing** beside **Chat with AI** on a company, board or project. It is also available inside the company/board AI window, project chat (including maximized chat), task controls and the company activity dashboard. The paired buttons stay together and wrap on narrow screens. A board opens a briefing for that board's projects; a company opens its company briefing; project and task controls open that project's briefing. The selector can switch between companies, boards and projects, including empty and unassigned boards. Viewers see a disabled Audio button with an Editor-access explanation.

Press **Start briefing** for a spoken summary. **Fresh summary** asks again using current saved tasks, comments, checklists and dates. Replies are saved under the **Audio briefing** conversation in that scope. The panel can replay any of its saved replies and offers three English speaking voices.

Press **Record question**, allow the microphone, and press **Finish recording**. Review the transcript and press **Send question**. Recording stops after one minute. Typed questions work as well. Replies always use Ask mode: speaking with the briefing AI does not edit tasks or start agents. Close the panel or change the selected scope to release the microphone and stop pending playback. A browser that blocks automatic playback shows a Play control.

## Architecture and access

Summaries use the existing project/company/board chat worker and its configured AI funding. Speech generation and transcription use a private Speaches service, with Kokoro and faster-whisper models. The service needs no OpenAI API key. The current integration uses English transcription and the `af_heart`, `am_michael` and `bf_emma` voices.

`BOARDLY_AUDIO_URL` points to the private service. `BOARDLY_AUDIO_TOKEN_FILE` supplies its bearer token from a private file; `BOARDLY_AUDIO_TOKEN` is an alternative for private server environment configuration. Never put this token in the browser or repository. Voice status requires both configured models to be installed. An unavailable service leaves written questions usable.

Authenticated routes are `/api/audio/{project|company|board}/:id/status`, `/transcribe`, and `/speech`. Project audio follows existing Editor access. Company and board audio follow the existing owner-only organization AI boundary. Routes resolve the signed-in workspace and recheck permissions after generation; a caller cannot play another project's or account's reply. Speech accepts a saved assistant reply ID, rather than arbitrary client text. Existing secret redactors run before synthesis. Requests are bounded to three concurrent audio operations globally, one per actor, 20 requests per actor per minute, 12 MB per recording, 6,500 characters per reply and 90 seconds per provider operation.

Microphone recordings are held in memory for transcription. The generated transcript stays in the input until Send is pressed; the submitted text and AI response then use the existing saved chat history. Generated MP3 audio is returned without HTTP caching and held in a browser object URL until stopped or closed. Boardly does not save microphone recordings or generated audio files in project storage. Audio and transcription are processed by the configured private voice service.

## Deployment and verification

Build the voice image with `docker build -f Dockerfile.audio -t boardly-audio:local .`. It derives from pinned Speaches v0.8.2 and sets ONNX's inference pool to four threads with spinning disabled, matching a four-CPU container limit. The upstream host-sized pool throttles heavily under CPU limits. Keep the service limited to 4 GB RAM on Boardly's private Docker network. Its optional host port must bind only to loopback. Protect it with `API_KEY`, set `ENABLE_UI=false` and `LOG_LEVEL=warning`, and persist `/home/ubuntu/.cache/huggingface/hub` in a volume. No additional public endpoint is required.

Install `speaches-ai/Kokoro-82M-v1.0-ONNX` and `Systran/faster-whisper-small.en` through the authenticated `POST /v1/models/{model_id}` endpoint. Set `WHISPER__INFERENCE_DEVICE=cpu`, `WHISPER__COMPUTE_TYPE=int8`, `WHISPER__CPU_THREADS=2`, and `WHISPER__TTL=900`. Use the floating-point Kokoro model: its int8 variant was substantially slower on the deployment CPU. This pinned image requires explicit model installation; do not assume newer source documentation's preload settings are implemented.

Provider references: [Speaches installation](https://speaches.ai/installation/), [speech generation](https://speaches.ai/usage/text-to-speech/), [configuration](https://speaches.ai/configuration/). OpenAI Realtime was evaluated using the [official WebRTC guide](https://developers.openai.com/api/docs/guides/realtime-webrtc); this implementation uses the existing Boardly Ask workflow and the private speech service.

Run `node test/audio.js` for authorization, redaction, validation, concurrency, revocation and snapshot checks. `test/audio-browser.cjs` uses the existing browser fixture plus a generated audio sample in the operations directory to test playback, microphone cleanup, scoped conversations, saved history and mobile layout. Verify real synthesis/transcription and a real AI response separately from fixture tests before publishing. There is no new database schema; rollback replaces the app image and audio configuration while preserving current conversations and task data.
